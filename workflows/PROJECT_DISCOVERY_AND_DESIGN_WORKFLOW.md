# Project Discovery and Design Workflow

## 1. Understand
Identify user goal, audience, primary tasks, product context, content, success conditions, constraints, and scope.

## 2. Inspect
Review repository structure, framework, routes, styling, design tokens, components, assets, data contracts, tests, and current behaviour.

## 3. Research
Analyze supplied references. Conduct proportionate research into relevant products, patterns, libraries, and platform conventions. See `REFERENCE_RESEARCH_WORKFLOW.md`.

## 4. Define direction
Describe the visual concept, layout language, typography, palette, imagery, component character, and motion principles. Obtain approval for major changes.

## 5. Plan experience
Map navigation, information architecture, page hierarchy, primary flows, component inventory, responsive behaviour, and UI states.

## 6. Plan implementation
Select compatible tools, define design tokens, identify dependencies, preserve existing architecture, and plan verification.

## 7. Implement incrementally
Build the highest-value structure first. Keep components coherent, interactions functional, and content truthful. Verify after meaningful milestones.

## 8. Inspect and refine
Use the visual audit checklist. Check representative viewport sizes, states, keyboard operation, and motion. Fix and reinspect.

## 9. Evaluate and report
Apply the weighted score, check critical gates, and complete the delivery report.

## Proportionality
- Small component change: local inspection, focused implementation and checks.
- Single feature/page: flow and state planning, responsive implementation, visual audit.
- New product/major redesign: complete discovery, research, direction decision, architecture, implementation, and full evaluation.
